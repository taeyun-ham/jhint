# 버그 고치기 (재현 테스트 먼저)

규칙 원본: admin-starter `templates/project/CLAUDE.md` 6장 "테스트 (TDD)"·"보이스카우트 규칙"(2026-11-27 CTO가 웹팀에도 적용). 원본 스킬: admin-starter `templates/project/.claude/skills/bugfix-tdd`.

1. 버그인지 개선인지 가른다. 애매하면 사용자에게 묻는다. 버그 브랜치에는 개선을 섞지 않는다(`fix/<짧은 이름>-<MMDD>`, 로컬 브랜치).
2. **테스트 도구 확인**: jhint는 처음에 Vitest가 없다. `package.json`에 `test` 스크립트가 없으면 이 버그 브랜치의 첫 커밋으로 넣는다: `npm i -D vitest` + `"test": "vitest run"`. 이 커밋은 도구만(테스트·고침 섞지 않음).
3. **재현 테스트(빨강)**: 보고된 동작을 그대로 표현하는 테스트를 쓴다. 가장 낮은 층에서 재현한다.
   - 순서: 순수 함수(형식·검사·주소 처리, `src/`·`worker/`) → Worker 요청 처리(`worker/index.ts`에 `Request`를 넣어 응답 상태·본문 확인) → 컴포넌트(RTL + user-event, 역할·라벨·글자로 찾기).
   - 테스트 파일은 대상 옆 `*.test.ts(x)`. `it`은 "무엇을 하면 어떻게 된다", given·when·then 표시.
   - `npm test`로 **실패하는 것을 확인**하고, 실패 메시지가 보고된 증상과 같은지 본다.
   - 이 테스트만 커밋한다: `test(<범위>): <증상> 재현`.
   - 모양(색·간격·배치) 버그는 테스트 대상이 아니다 → 고치고 PC 1440·폰 390 사진 → 디자인실.
4. **고침(초록)**: 원인을 고친다. 테스트를 느슨하게 해서 덮지 않는다. `npm test`·`npm run check`·`npm run build`가 모두 통과하면 커밋한다: `fix(<범위>): <원인 한 줄>`.
5. **정리(선택)**: 고친 곳 주변 정리는 동작을 바꾸지 않는 범위에서 따로 커밋한다: `refactor(<범위>): …`. 관련 없는 파일은 건드리지 않고 연락함에 적어만 둔다.
6. **로컬 확인**: 화면은 `npm run dev:local`의 :5180, 주소·상태 코드(_redirects·404·/api/inquiry)는 wrangler dev 127.0.0.1:8791에서 증상이 사라졌는지 본다. 요청 기록은 `docs/requests/YYYY-MM-DD-*.md`.
7. **푸시하지 않는다**: jhint는 main 병합 = 운영 배포. 사용자가 "배포해"라고 할 때만 push → PR → squash 병합.
8. PR 본문(한국어)에 적는다:
   - 커밋 순서(도구 → 재현 → 고침 → 정리)와 각 커밋 해시
   - 원인 한 줄, 고친 방법 한 줄, 같은 원인이 다른 곳에 있는지 찾아본 결과
